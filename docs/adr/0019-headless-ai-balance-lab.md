# Headless AI Balance Lab

Rune Lanes uses a headless Rust CLI and checked-in policy config for dev-only AI self-play. Keeping simulations inside the authoritative rules engine avoids player/archive persistence and makes AI promotion a small reviewable config diff; player-visible spectator mode, arbitrary card-effect DSLs, external model calls, and automatic rule-balance promotion are intentionally out of scope.

AI selection filters configured rule candidates through the core command query facade for the current phase. The baseline policy repositions before Movement setup Cards and re-evaluates movement after each summon; the aggressive policy retains its configured summon-first preference. Both use the same phase-aware decision for command selection and paced compatibility advancement, preserve historical Card windows, and can choose useful higher-priority Spell responses over a pending stack.

Simulation setup is prepared once before a suite runs. One in-process module owns strict rule-preset deserialization, validation, Card/Unit resolution and seeded match construction. Its immutable prepared setup creates independent mutable matches using the core's system recipes and AI-lab construction helpers. The self-play loop receives constructed state and retains its strict command path; CLI/report/sample code does not mutate setup state. Unsupported Card kinds in Unit setup fail during preparation rather than after validation succeeds.

Card evidence reports reuse that self-play loop over paired core Card test scenarios. Inputs contain complete candidate/baseline definitions with exact draft-version or published-revision provenance, explicit seeded scenarios, the AI policy configuration and selected policies, the tested Duel side and an action limit. Preparation validates both definitions through the core's shared experimental bounds and prepares every initial scenario before self-play starts. Cases must have an empty authored Card list; the comparison gives one input Card to the tested side and replaces matching recipe copies in its seeded draw pile with the same exact definition. Other scenario state stays identical across the pair.

The report retains all inputs, the core default ruleset version and compiled built-in definitions for reproducibility evidence. It records Card play action indices, surviving newly summoned matching Units, actual outcomes and descriptive paired deltas. Whole-game replay event totals include damage (including combat/counterattacks), healing and draws; these are recorded amounts rather than effective HP/Unit armor changes. Replay events lack consistent source-Card attribution, so totals are not labeled as effects caused by the input Card. Timeouts and illegal actions remain incomplete outcomes. Reports contain no synthetic balance score, promotion gate or automatic verdict.

The dev-only `ai-lab compare-cards` command consumes self-contained caller-supplied snapshots and writes an explicit report file without Account or match persistence. Authenticating and resolving persisted Account sources is a separate application delivery. Reproducing a report requires a compatible core and built-in catalog; this evidence does not implement historical match catalog freezing.
